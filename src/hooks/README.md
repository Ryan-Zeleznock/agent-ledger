# hooks
**Job:** Turn a Claude Code or Codex hook event (stdin JSON) into an `IncomingCall` (PreToolUse) or an `Outcome` (PostToolUse; Claude Code's PostToolUseFailure), turn the pipeline's `HookDecision` back into the exact `hookSpecificOutput` JSON the agent expects, and define the two-process **watchdog** that is the only thing either agent executes
**Depends on:** types only (the pipeline is wired in by the `hook` command after Gate 2, not by import; the watchdog imports nothing from this package at all)
**Does NOT:** decide anything, execute tools, or read the registry
**Spec:** docs/spec.md §3, 6, 7

Why it exists: an MCP proxy never sees a coding agent's built-in tools (Claude Code's Bash, Edit, Write, WebFetch; Codex's Bash, apply_patch). Hooks fire for built-in and MCP tools in both agents and can be enforced by an admin (Claude Code managed settings `allowManagedHooksOnly`; Codex `requirements.toml` `allow_managed_hooks_only`). Local mode is therefore hook collector + MCP proxy, for both agents (ADR-005).

**Two agents, one `agent` argument.** `parseHookInput`, `toIncomingCall`, `toOutcome` and `formatPreToolUseOutput` take `agent: "claude-code" | "codex"`. The wire formats share the core (`session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id`) and the output block, so one code path with two type sets is simpler than a second module. Verified 2026-09-29: Claude Code at https://code.claude.com/docs/en/hooks; Codex at https://learn.chatgpt.com/docs/hooks plus the generated schemas in openai/codex `codex-rs/hooks/schema/generated`. Fixtures: `test/fixtures/claude-code-*.json` (PreToolUse, PostToolUse, PostToolUseFailure) and `test/fixtures/codex-*.json` (PreToolUse, PostToolUse; Codex has no failure event).

**Codex differences that change behaviour.** `model`, `turn_id`, `permission_mode` required; `transcript_path` nullable; `tool_input` is "any JSON value" (a non-object is refused → deny); file edits always arrive as `apply_patch` (`Edit`/`Write` are matcher aliases only); a failed command still arrives as `PostToolUse`, so the Codex outcome is `ok` = "ran and returned"; and **`permissionDecision: "ask"` is unsupported: Codex marks the hook failed and CONTINUES the call**, so the Codex formatter rewrites `ask` to `deny` with `CODEX_ASK_UNSUPPORTED_REASON`. Under Codex, `require_approval` needs a Slack channel to ever become an allow.

**Naming.** Built-in tools map to `builtin:claude-code` or `builtin:codex` (`BUILTIN_SERVERS[agent]`). `mcp__<server>__<tool>` maps to `<server>/<tool>`, server segment verbatim. Neither agent can put a `:` in that segment: Claude Code allows only `[A-Za-z0-9_-]` in MCP server names and rewrites the rest to `_`; Codex allows `:` in a raw server name (`codex mcp add`) but every hook-visible MCP name passes `sanitize_responses_api_tool_name`, which keeps only `[A-Za-z0-9_]`, so `builtin:codex` arrives as `mcp__builtin_codex__<tool>`. A server segment that normalises to `claudecode`, `builtinclaudecode`, `codex` or `builtincodex` is refused outright under either agent (throw → deny). A Claude Code tool event with `mcp_server` provenance but no `mcp__` prefix is refused too.

**Watchdog** (`runWatchdog`, `validateHandlerOutput`; spec §7). Verified for Claude Code: exit 2 blocks PreToolUse whether or not JSON is printed and even an `allow` JSON cannot override it; exit 0 without a decision, exit 1, unparseable or schema-failing stdout, a timed-out hook and a hook that can't start all let the call continue. Codex documents exit 2 + stderr as a block and treats unsupported output as a failed hook that continues. So the agent runs a tiny watchdog process (node built-ins only), which spawns the handler, owns stdout exclusively, captures the handler's stdout/stderr into bounded buffers, enforces `deadlineMs` on its own event loop (SIGKILL, no awaiting), validates the handler's payload against the exact schema and size bound, and emits **exit 2 for every deny and every failure path** (crash, non-zero exit, oversized/invalid/extra-key output, deadline, spawn failure, config or init failure) with the reason on stderr and a deny JSON on stdout. Only a validated allow (or, for Claude Code, ask) is exit 0. Residual limits: a missing watchdog binary, a watchdog killed by the OS, or a user-edited hook entry produce no output and both agents continue; mitigation is managed configuration (Claude Code `allowManagedHooksOnly`; Codex `requirements.toml` `allow_managed_hooks_only` + `[features].hooks = true`) plus a `SessionStart` heartbeat the report checks.
